# Commit-Regeln — Shinon Forge

> **Status:** current — Regeln und ihre Durchsetzung. **Stand:** 2026-10-08
> **Einstieg:** `docs/INDEX.md` · **Zahlen:** `docs/ZAHLEN.md`

Drei Regeln. Alle fail-closed. Keine Ausnahmen, kein Schalter.

## 1. Kein KI-Footer. Nie.

Verboten ist **jede Zeile, die eine Maschine als Autor ausgibt** — nicht nur die
eine Schreibweise, die ein Agent heute aus Gewohnheit produziert:

- `Generated with Codebuff 🤖`, `Generated by Codebuff`, `Made with Codebuff`
- `Co-Authored-By: Codebuff <noreply@codebuff.com>`, `Co-authored by Codebuff`
- `generated|made|written|created|powered` + `with|by` + Name, für Codebuff,
  Claude, ChatGPT, Copilot, Gemini, Cursor, Aider, OpenAI, Anthropic, Devin,
  Codex, Qwen — **in beliebiger Schreibweise**: mehrere Leerzeichen, Tabs,
  optionaler Doppelpunkt (`Powered by: ChatGPT`)
- jede Zeile, die mit `Generated …` / `Made …` beginnt (auch ohne bekannten Namen)
- Emoji-Signaturen (`🤖`, `🦊`) mit `generated|written|made|created`
- `co-authored-by:` überhaupt (auch für Menschen — eine Signatur, nicht zwei)

Die Muster stehen in `scripts/lib/commit-text.mjs` (`FORBIDDEN_LINES`). Es gibt
genau eine Quelle; Hook, Gate und CI lesen dieselbe.

**Zeilenweise, nicht Fließtext.** Eine Signatur ist eine Zeile; geprüft wird die
Zeile — dafür aber an **jeder** Position der Nachricht, auch mitten im Body. Eine
Signatur, die sich durch ein Tab oder ein zusätzliches Leerzeichen versteckt, ist
noch dieselbe Signatur.

## 2. Der Vannon-Trailer ist Pflicht

Der letzte inhaltliche Block jeder Commit-Nachricht ist:

```text
created by VANNON — Volatile Agent Needing No Other Nonsense, Never Overly Nice, Never Average Vibe
```

Whitespace und Gedankenstriche werden gefaltet (`–`/`-` sind gleichwertig),
der Trailer zählt in den letzten drei inhaltlichen Zeilen.

## 3. Die Wort-Regel ist Pflicht

Eine Commit-Nachricht erzählt die Änderung — kein Stichwort, keine anonyme
Zahl. Drei Zusagen, geprüft am Inhalt (ohne Trailer, ohne `#`-Zeilen):

1. **Umfang:** mindestens **150 Wörter** (Whitespace-getrennt; Zahlwörter und
   Code zählen mit).
2. **Daten namentlich:** mindestens eine konkrete Referenz — Pfad mit Endung
   (`scripts/lib/commit-text.mjs`), Commit-SHA (7–40 Hexzeichen), Messung
   (`401/401`), Exit-Angabe (`Exit 0`) oder Nummer (`Run 37571432238`, `#127`).
   Eine Zahl ohne Herkunft ist kein Beleg.
3. **Bildsprache:** mindestens ein Vergleichs-/Bildmarker aus der festen Liste
   in `scripts/lib/commit-text.mjs` (`BILDSPRACHE_MARKERS`: `wie ein`,
   `wie eine`, `als wäre`, `als ob`, `bildlich`, `Metapher`, `Szene:` …).
   Die Liste ist bewusst eng: Der Wächter prüft einen Marker, kein
   Stilgefühl. Wer einen Marker vermisst, trägt ihn dort ein — mit Test —,
   statt ihn zu behaupten.

Die Muster stehen in `scripts/lib/commit-text.mjs` (`WORD_MIN`,
`NAMED_DATA_PATTERNS`, `BILDSPRACHE_MARKERS`, `wordViolations`). Es gibt genau
eine Quelle; Hook, Gate und CI lesen dieselbe. Der lokale prepare-Hook tauscht
nur Footer — 150 Wörter schreiben kann er nicht; die Wort-Regel gilt deshalb
**nur fail-closed** (commit-msg-Hook und CI lehnen ab, niemand repariert).

## Durchsetzung

| Ort | Datei | Verhalten |
|---|---|---|
| Lokal, vor dem Commit | `.githooks/pre-commit` | Fährt **nur** die schnelle Linie (`npm test`: statisches Gate + lokale Slices, Sekunden). Der volle Lauf (`test:full`) gehört in CI — das Gate pinnt, dass kein langsamer Pol im Hook steht. |
| Lokal, vor der Prüfung | `.githooks/prepare-commit-msg` | **Tauscht** verbotene Footer gegen den Vannon-Trailer (`--fix`). |
| Lokal, verbindlich | `.githooks/commit-msg` | **Fail-closed**: ohne Trailer, mit Footer kein Commit. |
| CI, immer | `.github/workflows/commit-guard.yml` | Läuft bei jedem `push`, `pull_request` und auf Zuruf (`workflow_dispatch`), ohne `paths`-Filter, ohne `continue-on-error`; ruft `commit-guard.mjs --ci` auf. |
| Bereich | `scripts/lib/ci-range.mjs` | Leitet ab, **welche** Commits geprüft werden — und wird im Zweifel **nie enger**: unbestimmter Bereich ⇒ volle Historie. |
| Gate | `scripts/gate/plugins/commit-trailer.mjs` | Prüft, dass Regeln, Hooks und CI-Job existieren **und wirken** (eingefrorene Signatur muss abgelehnt werden). |
| Tests | `scripts/gate/tests/commit-trailer.test.mjs` | Regel-Verhalten, Tausch, Hook-Kette, Bereichs-Scan in einem echten temporären Repo. |

Aktivieren (einmal pro Klon):

```bash
npm run hooks:install     # setzt core.hooksPath=.githooks und legt die Hooks an
```

Prüfen:

```bash
npm run commit:guard -- --last 5          # die letzten 5 Commits
npm run commit:guard -- --range <a>..<b>  # ein Bereich
npm run commit:guard -- --ci              # genau das, was CI prüft
npm run commit:guard -- --all             # Audit der ganzen Historie
npm run commit:guard -- --stdin < datei   # Trockenlauf der eigenen Nachricht
npm run commit:check-file -- datei        # derselbe Lauf über --file (ohne --fix)
```

Der Trockenlauf ruft `checkMessage` auf — **denselben** Regelsatz wie der
Commit-msg-Hook und CI, ohne Tausch und ohne Git-Zugriff. Er ist der billige
Weg, die Checkliste vor dem ersten `git commit` abzuhaken, statt den Hook als
Fehlermeldung zu benutzen.

## Eine Prüfung, zwei Werkzeuge — mit Invariante

Prüfen (`checkMessage`) und Tauschen (`swapTrailer`) benutzen **dasselbe**
zeilenweise Prädikat (`forbiddenLabelsOf`). Daraus folgt die Eigenschaft, die die
Tests pinnen (330 Signatur-Varianten × Schreibweisen, plus Korpus):

```text
swapTrailer(n) !== n   ⇒   checkMessage(n).ok === false
checkMessage(n).ok     ⇒   swapTrailer(n) entfernt keine Inhaltszeile
```

Heißt: was der lokale Hook entfernt, lehnt CI auch ohne Hook ab — und was CI
durchwinkt, wird lokal nicht heimlich repariert. Vorher waren das zwei getrennte
Prüfungen (die Prüfung sah nur den Nachrichten-Anfang, der Tausch jede Zeile):
lokal wurde „repariert", was CI akzeptiert hätte.

## Im Zweifel mehr prüfen, nie weniger

Der Wächter prüft nie weniger, als der Push hinzufügt. Kann er den Bereich
nicht bestimmen — Force-Push auf einen verschwundenen Stand, flacher Klon ohne
Hauptlinie, unbekanntes Event, kaputte Event-Datei — dann prüft er die **volle
Historie** der Spitze, nicht bloß den Kopf-Commit. Die Bereichslogik liegt
deshalb in `scripts/lib/ci-range.mjs` (reine Funktion, getestet) und nicht als
Shell-`if` im Workflow.

Ein Wächter, der im Zweifel weniger prüft, ist kein Wächter.

### Neuer Branch: Spitze minus Hauptlinie (2026-10-13)

Der erste Push eines Branches (`before` ist der Null-SHA) fiel früher unter die
volle Historie — und machte damit **jeden** neuen Branch rot, sobald irgendwo in
der Vergangenheit ein Commit ohne Trailer stand (gemessen: der Branch-Push
`358979d` war rot, obwohl seine eigenen Commits sauber waren). Das ist kein
„mehr prüfen", sondern falsch prüfen: die Hauptlinie wurde bei ihrem eigenen
Push schon gerichtet. Seit 2026-10-13 gilt deshalb: liegt `origin/main` im Klon
(CI checkt mit `fetch-depth: 0` aus), prüft der Wächter die Spanne
**Merge-Basis..Spitze** — genau das, was der Branch hinzufügt, vollständig.
Fehlt die Basis, gilt weiter die volle Historie (fail-closed). Die Regel oben
bleibt: unbestimmt ⇒ volle Historie. Neu ist nur, dass ein neuer Branch mit
bestimmbarer Basis nicht mehr „unbestimmt" heißt.

## Presets — eine Policy, drei Pfade

Die Regeln sind Daten: `docs/contracts/commit-policy.json` (Vertrag
`shinon.commit-policy/v1`). `scripts/lib/commit-policy.mjs` validiert sie,
`scripts/lib/commit-policy-file.mjs` wählt sie aus; Hook, CLI und CI lesen
dieselbe Datei über `scripts/commit-guard.mjs`.

| Preset | Trailer | Wort-Regel | Betreff | Reparatur |
|---|---|---|---|---|
| `shinon-maintainer` (Voreinstellung) | Pflicht | 150 Wörter, Daten, Bild | frei | `--fix` tauscht Footer |
| `minimal` | keine | keine | frei | `--fix` tauscht Footer |
| `conventional` | keine | keine | `typ(scope)!: …` | `--fix` tauscht Footer |
| `strict-evidence` | Pflicht | 150 Wörter, Daten, Bild | frei | keine — fail-closed |

**Fußboden, von keinem Preset abwählbar:** Signatur-Footer und `co-authored-by`
bleiben verboten. Die Prüfung ist kein Preset-Feld; der Vertrag hat dafür
`floor` (beide `true`), und ein Preset kann die Felder gar nicht ausdrücken —
unbekannte Schlüssel lehnt der Validator ab.

**Auswahl**, Vorrang von oben nach unten:

1. `--policy-file <datei>` (ein vollständiger Vertrag)
2. `--policy <preset>`
3. `SHINON_COMMIT_POLICY=<preset>`
4. `.shinon/gate-profile.json` → `{ "commitPolicy": { "preset": "conventional" } }`
5. Voreinstellung `shinon-maintainer` (das unveränderte Repo-Verhalten)

Ein defekter Input — kaputtes JSON, unbekanntes Preset, unbekannter Schlüssel,
abgeschwächter Fußboden — endet mit **Exit 2**. Es gibt keinen Rückfall auf
Ersatzregeln, in keinem der drei Pfade.

Die Reparatur bleibt begrenzt: `prepare-commit-msg` entfernt nur Zeilen, die die
Footer-Prüfung ablehnt, und hängt den Trailer an; Body und Prosa bleiben
bytegleich. Unter `strict-evidence` schreibt auch der prepare-Hook nichts.

Tests: `scripts/gate/tests/commit-policy.test.mjs` (Vertrag, Preset-Matrix,
Auswahl, Parität Hook/CLI/CI, Reparaturgrenze).

## Warum Tausch UND Fail-Closed

Lokal ist Reparatur erlaubt: Agenten produzieren Signatur-Footer aus Gewohnheit,
und ein Blockieren ohne Ausweg erzeugt Handarbeit oder `--no-verify`. Der
prepare-Hook tauscht sie mechanisch aus — der Commit enthält danach genau einen
Trailer.

In CI gibt es keinen Tausch. Dort gilt: liegt eine Signatur im geprüften
Bereich, ist der Job rot. Ein bereits gepushter Verstoß wird nicht repariert,
sondern gemeldet — sonst wäre die Prüfung verhandelbar.

Fail-closed heißt auch: der Job lässt sich nicht entschärfen. Das Gate
(`scripts/gate/plugins/commit-trailer.mjs`) prüft am Dateiinhalt, dass der
Workflow keine Pfad-/Branch-Filter hat, kein `continue-on-error: true` trägt und
den Prüfbereich nicht selbst im YAML ableitet.
